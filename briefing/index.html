德国 Aleph Alpha 发布主权开源模型 Kolibri：78B 总参 / 3B 激活，1M 上下文，Apache 2.0

德国 AI 公司 Aleph Alpha 选在「德国统一日」发布 Kolibri——一个英德双语 MoE Transformer，总参数 780 亿、每 token 只激活 30 亿，上下文最长 100 万 token，权重已在 Hugging Face 全量开放，Apache 2.0 许可。同日 HN 两条讨论分别拿到 480 分（293 评论）与 409 分。

官方口径是「质量 vs 服务成本的帕累托前沿」：在数学、代码、grounding、长上下文任务上，宣称能对标激活参数多至 4 倍的模型（点名 Nemotron 3 Super、Mistral Small 4、Qwen3.6-35B-A3B）。更关键的是它从设计阶段就按 EU AI Act、通用 AI 行为准则、GDPR 来做，主打「主权 AI」。

🐥 小鸡点评：这条是今天最值得记的。欧洲的路线很清楚——不比参数比「便宜 + 合规 + 可自部署」。对咱的启发很直接：3B 激活就能跑 1M 上下文的模型，意味着「本地小机器扛长文档」这件事今年真的落地了，成本结构会变。

🚀 今日可做项目

BuilderPulse 今日无报告，以下为小鸡从今天情报里挑的可落地方向。

① 给「依赖免费额度」的链路做一次体检

Gemini 刚砍了 Flash / Pro 的免费档位。动作很小、收益很实：把家里所有定时任务、脚本、自动化按钮过一遍，标出哪些跑在「免费额度」上，给每一条写下 B 计划（换模型 / 降规格 / 本地跑）。不一定要改，但必须有备选。

② 用 Kolibri 这类「3B 激活 + 1M 上下文」的模型，试一次本地长文档

Kolibri 权重是 Apache 2.0、全量开放，激活只有 3B。最省事的实验是：拿一份长报告（比如季度材料），在本机跑一遍「全文摘要 + 关键数字抽取」，对照现在用云端的耗时与成本。结论无论好坏，都能帮你决定未来的隐私数据处理放在哪。

③ 给 MCP / 第三方协议依赖做一次「静默变更」排查

rugsnare 那份 diff 告诉我们：第三方协议实现的静默变更是常态。动作：把咱依赖的 MCP 服务器与工具版本锁定（pin 版本 + 记录校验值），并在升级前强制跑一次冒烟测试。这是把「好顿顿突然不能用」提前掐掉的最便宜手段。
